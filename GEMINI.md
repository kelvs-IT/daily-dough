# Daily Dough Project Rules & Document-Generation Guidelines

## Automatic Document Saving Workflow

All documents created for the Daily Dough project must automatically be saved inside the project document folder:
`C:\Users\benzy\.gemini\antigravity-ide\scratch\daily-dough\documents/`
(Filesystem link: `C:\Users\benzy\.gemini\antigravity-ide\scratch\daily-dough\document/`)

### Applicable Document Categories
This workflow applies to any requested document related to Daily Dough, including:
- Project documentation
- System documentation
- Technical documentation & architectural specs
- Reports & verification summaries
- Research documents
- Meeting notes
- Testing documentation
- User manuals & operational guides
- Project proposals
- Other Daily Dough-related documents

### Core Rules & Constraints
1. **Target Directory**: Always save generated documents inside `C:\Users\benzy\.gemini\antigravity-ide\scratch\daily-dough\documents/`.
2. **No Root or Downloads Placement**: Do NOT save generated documents in the project root directory, Downloads folder, or other locations unless explicitly requested by the user.
3. **No Additional Folders**: Do not create another `document` or documentation folder.
4. **Document Integrity**: Do not move, overwrite, or delete existing documents without explicit user permission.
5. **Asset Separation**: Do not save source code, images, logos, or application assets inside the document folder.
6. **Supported File Formats**: Preserve appropriate file formats requested by the user (e.g., `.md`, `.pdf`, `.docx`, `.txt`, `.xlsx`, `.pptx`).
7. **Descriptive Filenames**: Use descriptive filenames that clearly identify the document's contents.
8. **Clarification Protocol**: If the requested document format or filename is unclear, ask the user first before proceeding.
9. **Failure Handling**: If the folder cannot be accessed, report the issue directly to the user instead of saving the file elsewhere.
10. **Delivery**: After creating any document, provide the exact file location and a clickable markdown link (`file:///...`) to the user.
